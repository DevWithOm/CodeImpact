## 2. Issues Discovered & Corrections Applied

### Issue 1: Documentation Example Mathematical Inconsistency
- **Discovery**: In `SAMAR_3_PHASE_6_IMPLEMENTATION_REPORT.md` and `SAMAR_3_PHASE_6_INTEGRATION_CONTRACT.md`, the representative finding example displayed `risk_score: 75.0` at the top level, but its factor breakdown listed:
  - Dependency exposure: 20.0
  - Cycle exposure: 15.0
  - Entry-point exposure: 0.0
  - Test-impact evidence: 15.0
  - Finding evidence: 10.0
  - Structural exposure: 5.0
  The sum of those listed factors was $20 + 15 + 0 + 15 + 10 + 5 = 65.0$, conflicting with the top-level $75.0$.
- **Root Cause**: In the hand-formatted markdown example, `finding_evidence_uncertainty` omitted the $+5.0$ additive bonus for `evidence_class == "inconclusive"`, which in the actual code evaluates to $10.0 + 5.0 = 15.0$. With finding evidence at $15.0$, the true score for that finding is $20 + 15 + 0 + 15 + 15 + 5 = 70.0$.
- **Correction Applied**: Updated the example JSON in both `SAMAR_3_PHASE_6_IMPLEMENTATION_REPORT.md` and `SAMAR_3_PHASE_6_INTEGRATION_CONTRACT.md` to display the exact outputs generated by `calculate_risk_score`:
  - `risk_score`: **70.0**
  - `finding_evidence_uncertainty`: **15.0** (reason: `"Exported symbol carries external consumer and dynamic import risk.; Static scan evidence is inconclusive; heightened review uncertainty."`)
  - `average_risk_score` in summary: **70.0**
  - Factor sum: $20.0 + 15.0 + 0.0 + 15.0 + 15.0 + 5.0 = 70.0$ (Exact equality).

### Issue 2: Module Directory & Core Directory Matching Precision
- **Discovery**: When evaluating `top_dirs` in `score_dependency_exposure` and `is_core_dir` in `score_structural_exposure`, paths formatted as `src/services/payment.ts` were checked using raw `.startswith("services/")`, which failed because of the leading `src/` prefix.
- **Correction Applied**:
  - Implemented `_extract_module_dir(path)` using `Path(path).parent.as_posix()` so that `src/api/checkout.ts`, `src/workers/billing.ts`, and `src/admin/portal.ts` correctly evaluate to 3 distinct directory structures, while `src/module_0.ts` and `src/module_1.ts` share the single parent directory `src`.
  - Updated `score_structural_exposure` to inspect directory segments via `dir_parts = set(file_path.split("/")[:-1])`, correctly matching files in `services/`, `core/`, `api/`, `config/`, `shared/`, or `lib/` regardless of repository nesting.

### Issue 3: Inconclusive Evidence Rule Clarification
- **Investigation**: Audited whether `unused_export` ($10$ pts) and `evidence_class == "inconclusive"` ($+5$ pts) are additive or mutually exclusive.
- **Verification**: In `risk_scorer.py`, the rule is strictly **additive**:
  $$\text{F5 Score} = \min(15.0, \text{Category Base} + \text{Inconclusive Bonus})$$
  - `unused_export` ($10$) $+$ `inconclusive` ($5$) $= 15.0$
  - `unused_file` ($5$) $+$ `inconclusive` ($5$) $= 10.0$
  - `duplicate_code` ($8$) $+$ `inconclusive` ($5$) $= 13.0$
- **Correction Applied**: Updated `SAMAR_3_PHASE_6_SCORING_MODEL.md` to explicitly state the additive formulation and provide concrete examples matching the implementation.

## 4. Missing-Data & Preservation Audits

### 4.1 Missing-Data Behavior
- **Valid Empty Graph**: Successfully analyzed repository with 0 nodes/edges results in evaluated scores, high confidence, and complete analysis status (mitigations emitted, no crash).
- **Truncated Graph**: Sets `risk_confidence = "low"`, `analysis_completeness = "partial"`, and strictly suppresses mitigating observations to prevent false reassurance.
- **Unavailable Graph**: Sets `review_risk = "unknown"`, `risk_score = None`, `risk_confidence = "unknown"`, and `analysis_completeness = "unavailable"`.
- **Unmapped Finding**: Files outside repository or invalid paths receive `review_risk = "unknown"`, `risk_score = None`.
- **Missing Test Impact / Entry Points**: Omission of optional metadata defaults to 0 points without throwing exceptions or lowering the base score. Absence of tests is **never** treated as evidence of safety.

### 4.2 Preservation Audit
- **Deep-Copy Immutability**: All input findings are deep-copied before enrichment. Mutating the output leaves input findings byte-for-byte identical.
- **Field Retention**: Retains `finding_id`, `category`, `title`, `file_path`, `start_line`, `end_line`, `symbol`, `source_tool`, `description`, `evidence_class`, `evidence`, `risk_factors`, `metadata`, `direct_dependants`, `direct_dependencies`, `cycle_member`, `cycles`, `self_dependency_detected`, `test_impact`, and arbitrary unmodeled custom keys.

## 7. Remaining Limitations

1. **Static Analysis Horizon**: The Review-Risk Engine assesses static graph connectivity. Dynamic calls (`import()`, `eval()`, runtime dependency injection) cannot be detected via static analysis and are transparently disclosed under `uncertainties`.
2. **Heuristic Entry Points**: While manifest-declared entry points (`main`, `bin`, `exports`) have high confidence, fallback heuristics rely on standard conventions (`src/index.*`, `src/main.*`, `server.ts`).
3. **No Coverage Assertions**: Candidate tests identify modules that import the flagged code; they do not guarantee execution coverage or assertion validity.
